# 4S to Silver Challenge — LINE Bot

ระบบสะสมคะแนน 4S รายเดือนสำหรับกลุ่ม LINE บันทึกข้อมูลลง Supabase/Postgres และแสดงกติกาฉบับเต็มที่หน้า `/rules`

## ภาพรวม
- รับคำสั่ง 4S จาก LINE Messaging API และบันทึกเหตุการณ์ลงตาราง `events`
- คำสั่งที่ต้องแนบรูปจะรอรูปภาพถัดไปผ่านคิว `pending`
- มีหน้า Rank รวมคะแนนตั้งแต่ต้นเดือนปัจจุบันต่อเนื่อง พร้อมระดับ Level ทุก 100 คะแนน และหน้า Rules แบบสแตติก
- มีหน้า Profile สำหรับดูรูปโปรไฟล์ LINE คะแนน 4S รายบุคคล รายการคำสั่งวันนี้ จำนวนคำสั่งสะสมตั้งแต่ พ.ย. 2026 และธีมตาม Level (รูปจะแสดงเมื่อ LINE อนุญาตให้บอทเข้าถึงโปรไฟล์)
- เชื่อมระบบกับ Supabase เพื่อใช้งาน Postgres และ REST API เดียวกัน

## การเตรียมค่าใช้จ่าย
1. เปิดโครงการ LINE Messaging API แล้วสร้าง Channel Access Token
2. สร้างฐานข้อมูลบน Supabase (หรือ Postgres ที่เข้าถึงได้จากภายนอก)
3. เตรียมค่าแวดล้อมสำหรับการรันเซิร์ฟเวอร์

สร้างไฟล์ `.env` แล้วกำหนดค่าที่จำเป็น เช่น
```env
LINE_CHANNEL_ACCESS_TOKEN=xxxx
LINE_TARGET_ID=Uxxxxxxxxxxxxxx        # groupId หรือ userId ที่ต้องการ push ข้อความ
SUPABASE_URL=https://xxxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=xxxxx        # ใช้ service role สำหรับ insert/update
SUPABASE_DB_URL=postgresql://USER:PASSWORD@HOST:PORT/DATABASE
SCORE_TIMEZONE=Asia/Bangkok            # เวลาอ้างอิงสำหรับตัดรอบ (ค่าเริ่มต้น Asia/Bangkok)
WEEKLY_CRON=0 9 * * 1                  # ตัวอย่างตั้งเวลา push รายสัปดาห์
```
> หากเชื่อมต่อฐานข้อมูลที่ไม่ต้องใช้ TLS ให้ระบุ `?sslmode=disable` ใน `SUPABASE_DB_URL`

## ขั้นตอนติดตั้ง
1. ติดตั้ง dependencies
   ```bash
   npm install
   ```
2. สร้างตารางและ seed กติกาพื้นฐานเข้าสู่ Supabase (รันครั้งแรกหรือเมื่อ reset ระบบ)
   ```bash
   npm run init-db
   ```
   - สคริปต์จะตรวจสอบ/สร้างตาราง `events` และ `pending`
   - ฟิลด์คะแนนถูกบังคับเป็นชนิด `NUMERIC(12,2)` เพื่อรองรับคะแนนทศนิยม
3. เริ่มเซิร์ฟเวอร์
   ```bash
   npm start
   ```
   เซิร์ฟเวอร์จะเปิดที่ `http://localhost:3000` (หรือพอร์ตที่กำหนดใน `PORT`)

## Endpoint ที่สำคัญ
| Endpoint | คำอธิบาย |
|----------|-----------|
| `POST /webhook` | จุดรับ webhook จาก LINE (อย่าลืมตั้งค่าให้ส่ง raw body) |
| `GET /top10` | ดึงอันดับ Top 10 รายเดือน (รองรับ query `ym`) หรือคะแนนสะสมตั้งแต่เดือนปัจจุบันด้วย `scope=cumulative` |
| `GET /profile` | หน้าเลือกดู Profile รายบุคคล |
| `GET /profile/data` | ดึงคะแนน 4S รายเดือน คำสั่งวันนี้ และจำนวนคำสั่งสะสมตั้งแต่ พ.ย. 2026 (ต้องระบุ `user_id`, รองรับ `ym`) |
| `GET /countdown` | ดึงยอดเคส Countdown ที่เหลือในเดือน (รองรับ query `ym`) |
| `GET /months` | รายชื่อเดือนที่มีข้อมูลเพื่อใช้เลือกดูย้อนหลัง |
| `GET /weeks` | รายชื่อสัปดาห์ (ISO Week) ที่มีข้อมูล |
| `GET /` | หน้า Top 10 แบบเรียลไทม์ |
| `GET /rules` | หน้า Rules ตามลิงก์อ้างอิง |

## คำสั่ง 4S
- **S1 — PV และการนำเสนอ**: `/ppv <จำนวน PV>` สะสม PV รายเดือนและให้คะแนนเมื่อถึงเกณฑ์ 600 ถึง 15,000 PV; `/s1` นำเสนอสินค้าให้รายชื่อใหม่ (+1 และลด Countdown เคสสินค้า 1 เคส); ทั้งสองคำสั่งต้องส่งรูปตาม
- **S2 — การเพิ่มคน**: `/for <จำนวนสาย>` (+N), `/opp online` (+1), `/opp onsite` (+2 และลด Countdown เคสเล่าธุรกิจ 1 เคส), `/ABO` (+5), `/M` (+1), `/s2` (+1 และลด Countdown เคสเล่าธุรกิจ 1 เคส); ทุกคำสั่งต้องส่งรูปตาม
- **S3 — Moving Up Pin**: `/pin <พิน...>` รวมคะแนนพินที่มูฟเพิ่ม ใช้ได้ทุกวัน
- **S4 — การพัฒนาตัวเอง**: `/link` (+0.5 ต่อคำสั่ง ส่งได้หลายครั้งต่อวัน), `/book` (อ่านอย่างน้อย 10 หน้า, ระบุจำนวนหน้าได้, +0.5/วัน), `/product` (+0.1/วัน), `/ct` (+1/วัน), `/follow` (+1), `/hm` (ผู้ที่นัดคนมาเข้าร่วม HM ได้ +1 และผู้ที่เล่า HM ได้ +1), `/s4` (+1 พร้อมรูป), `/dm` (ทบทวนเป้าหมายและวิเคราะห์งานรายวันลงกลุ่มอัปไลน์ ต้องส่งรูปหลักฐานเพื่อรับ +1/วัน)
- **คำสั่งระบบ**: `/score`, `/rank` (แสดง Top 3), `/rules`, `/help`, `/groupid`; คำสั่งแรกของแต่ละแชทในวันที่ 5, 10, 15, 20, 25 หรือ 30 จะแสดง Top 10 เพิ่มในแชท

คะแนนหน้า Rank สะสมต่อเนื่องตั้งแต่เดือนพฤศจิกายน 2026 ซึ่งเป็นเดือนเริ่มนับ โดยรวมคะแนนของเดือนนี้และเดือนถัดไปเข้าด้วยกัน และไม่รวมเดือนก่อนหน้าเดือนเริ่มนับ Level เพิ่มขึ้นทุก 100 คะแนน (100 คะแนน = Level 1, 200 คะแนน = Level 2) พร้อมแถบแสดงความคืบหน้าสู่ Level ถัดไป

Countdown เป็นภารกิจรวมของทุกคน เริ่มต้นเดือนละ 50 เคสต่อหมวดและรีเซ็ตทุกต้นเดือน โดยนับเมื่อลงคะแนนหลังส่งรูปหลักฐานครบ เมื่อครบ 50 เคสจะปลดล็อกเฟส 2 โบนัสให้นับต่อจนถึง 100 เคสต่อหมวด คำสั่งแรกของวันในระบบจะแจ้งความคืบหน้าและจำนวนเคสที่เหลือของเฟสปัจจุบันในแชท ส่วนหน้า Rank แสดงจำนวนเคสสะสมของเดือนปัจจุบันและเฟสปัจจุบัน และเมื่อมีเคสที่นับเข้า Countdown ระบบจะส่งข้อความเชียร์พร้อมความคืบหน้าให้

คำสั่งที่ระบุว่าต้องแนบรูปให้พิมพ์คำสั่งก่อนแล้วส่งรูปในข้อความถัดไป คะแนนรายวันจำกัดตามที่ระบุในหน้า `/rules`
ทุกคำสั่งสามารถพิมพ์รายละเอียดต่อท้ายได้ โดยคำสั่งที่ต้องระบุจำนวนหรือประเภทให้ใส่ข้อมูลนั้นก่อน เช่น `/ppv 600 ยอดเดือนนี้`, `/for 5 โทรติดตามรายชื่อใหม่` หรือ `/opp onsite คุณเอ` รายละเอียดจะถูกบันทึกเมื่อคำสั่งนั้นสร้างรายการคะแนน

## การ Deploy
- รองรับการทำงานบน Render/Heroku/Vercel ฯลฯ ที่ใช้ Node.js ได้
- ต้องกำหนด webhook URL ของ LINE ให้ตรงกับ `<BASE_URL>/webhook`
- ตั้งค่า cron ผ่าน environment (`WEEKLY_CRON`) เพื่อให้ระบบ push สรุปรายสัปดาห์อัตโนมัติ

## การดูแลรักษา
- ไฟล์ log ในโฟลเดอร์โปรเจ็กต์ถูกลบออก ให้ตรวจสอบ log ผ่าน platform ที่ deploy แทน
- ตรวจสอบค่า Access Token ของ LINE และ Supabase Service Role ให้อัปเดตอยู่เสมอ
- สำรองฐานข้อมูลผ่าน Supabase อย่างน้อยเดือนละครั้งเพื่อกันข้อมูลสูญหาย

> หากมีการแก้กติกาใหม่ สามารถแก้ไขหน้า `views/rules.html` ให้ตรงกับลิงก์อ้างอิง และปรับเงื่อนไขใน `logic.js` เพิ่มเติมได้
